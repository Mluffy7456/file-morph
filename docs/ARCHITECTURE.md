# Архитектура FileMorph

## Цели и границы

FileMorph — локальное Windows-приложение для конвертации и небольших операций с файлами. MVP предусматривает обработчики форматов, пакетные задания, очередь, пресеты, историю, полезный предпросмотр и интеграцию с Проводником.

## Структура решения

- App (C# / WPF): представление, команды пользователя и встроенный обработчик изображений через Windows Imaging Component (WIC).
- Core: доменные модели, статусы заданий, возможности обработчиков и контракты. Не зависит от WPF и конкретных движков.
- Infrastructure: запуск внешних CLI-движков, файловая система, регистрация обработчиков и адаптеры.
- Core.Tests: быстрые unit-тесты доменных правил.
- Интеграция с оболочкой Windows должна быть отдельным компонентом после технического прототипа; COM-код не смешивать с UI.

Архитектура — модульный монолит, не микросервисы. Движки конвертации запускаются отдельными процессами для изоляции сбоев и поддержки отмены; первый WIC-обработчик использует системный компонент без внешнего процесса.

## Контракт обработчика

Каждый обработчик объявляет идентификатор, поддерживаемые входные/выходные расширения и операции. Приложение проверяет возможности до запуска и объясняет недоступные действия. Расширение файла — подсказка, а не доказательство типа содержимого.

## Первый вертикальный сценарий

Реализована базовая конвертация PNG, JPEG, BMP, TIFF и GIF через WIC:
1. Пользователь выбирает файл диалогом или перетаскивает его в окно.
2. Выбирает формат назначения.
3. Приложение подбирает свободное имя рядом с исходником.
4. Изображение кодируется во временный файл в папке назначения.
5. Итог публикуется через перемещение без разрешения перезаписи.
6. UI показывает прогресс и путь результата либо сообщение об ошибке.

Ограничения первой версии: анимированные изображения сводятся к первому кадру; AVIF, HEIC и WebP требуют отдельного движка; интеграционные тесты самого WIC-обработчика ещё предстоит добавить.

## Жизненный цикл задания

1. Проверить входной файл и выбранную операцию.
2. Выбрать путь назначения; по умолчанию рядом с исходником.
3. Не допускать перезаписи исходника и молчаливой замены существующего результата.
4. Создать уникальный временный файл в контролируемом каталоге.
5. Запустить движок через ProcessStartInfo.ArgumentList без shell-интерпретации, если используется внешний движок.
6. Поддержать отмену, ограниченный вывод логов и обработку кода завершения.
7. Проверить наличие и базовую корректность результата.
8. Переместить результат в итоговый путь, по возможности атомарно.
9. Безопасно очистить временные файлы; никогда не удалять исходник.
10. Записать результат в локальную историю после определения схемы и срока хранения.

## Безопасность и конфиденциальность

- Нет телеметрии и сетевых запросов во время обычной обработки.
- Возможная проверка обновлений — отдельная отключаемая функция.
- Не строить командные строки shell; передавать аргументы отдельными элементами.
- Ограничивать вывод stdout/stderr и длительность процессов.
- Не запускать неизвестные плагины автоматически; MVP использует встроенные обработчики.
- Не записывать содержимое пользовательских файлов в логи.
- Обрабатывать повреждённые файлы, конфликты имён, отмену, нехватку места и сбои движков.
- Проверять лицензии поставляемых движков до публикации.

## UI и визуальная система

- WPF; тёмная тема по умолчанию, светлая альтернатива.
- Soft Tech: сбалансированная плотность, мягкие карточки с тонкими границами, нейтральная современная типографика.
- Серебристо-белый акцент на графитовой основе.
- В полном окне логотип включает знак и надпись FileMorph; в иконке используется только знак.
- Анимация сборки/распада геометрии декоративна и не управляет логикой конвертации. Учитывать уменьшение движения.

## Совместимость и Alpha

Windows 11 — основная платформа. Windows 10 поддерживается, если это возможно без компромиссов по UX и безопасности. Интеграцию Explorer нужно отдельно проверить на поддерживаемых версиях Windows.

Перед Alpha обязательны: чистая сборка и тесты Windows CI; unit- и интеграционные тесты; проверки исходников, конфликтов выходных имён, отмены, повреждённых файлов и временных файлов; проверка установки/удаления и интеграции; проверка Portable на чистой VM; аудит лицензий и двуязычная документация.
